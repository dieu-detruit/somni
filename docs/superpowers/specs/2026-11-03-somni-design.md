# Somni 初版設計案

状態: 2026-11-03 ユーザー承認済み。名称Somnio、公開GitHubとCodemagicでビルド・TestFlight配信。最重要の成果は翌朝の主観的な休息感。

## 目的

iPhoneで睡眠用の音を流し、翌朝にApple Watchの睡眠記録と本人の感想を確認する個人向けアプリ。名称は作業ディレクトリに合わせてSomniを仮称とする。SwiftUIでiOS/watchOSのネイティブアプリを作る。

科学的な根拠と制約は[調査資料](../../research/evidence-review.md)を参照。モノラルビートの効果を確約せず、自分に合う音を記録から探せることを初版の価値とする。

## 検討した構成

1. **iPhoneで再生、Watchの標準睡眠記録を翌朝に読む（採用）**。常時動作・独自睡眠判定が不要で、音と睡眠の振り返りを早く試せる。睡眠中に段階に応じて音を変えることはできない。
2. **Watchで夜間計測して即時制御**。希望には近いが、長時間実行・サンプル配信・判定精度・電池消費の検証が先に必要。初版では採用しない。
3. **外部EEGで位相同期刺激**。研究に近い制御が可能になる余地はあるが、追加機器と別の開発が必要。今回のiPhoneとWatchという前提を超える。

ユーザーの回答: 「apple watchによるフィードバックにすぐ意味を見いだせないなら一旦watchはただの記録で大丈夫」。これを受け、1を選ぶ。以下のOS・画面・実装詳細は開発側の提案であり、ユーザー指定ではない。

## 初版の体験

- iPhoneの「今夜」で環境音のみ／環境音＋一般的なモノラルビートを選ぶ。初期は低音量、30分タイマー。15/30/60分・連続の選択とフェードアウトを用意する。
- 開始・停止・再生中の設定変更を記録。ロック中も再生。通話等の割り込みでは停止状態を反映し、勝手に再開しない。出力先変更時は安全に停止する。
- 翌朝の「記録」で前夜の再生時間、音の設定、Apple Watch由来の推定睡眠時間と段階を表示。寝つきと休息感を各1〜5で記録し、メモを付ける。
- Watchアプリでは前夜の記録を表示し、朝の休息感を入力できる。睡眠の測定自体はApple標準の睡眠記録を使う。Watchのアプリを開き続ける必要はない。
- 睡眠記録がまだ同期されていない場合は取得できたデータの時刻と再取得ボタンを表示する。データなし・読み取り拒否・未装着を断定しない。

## 構成

提案する最低OSはiOS 17 / watchOS 10。SwiftUI、AVFoundation、HealthKit、WatchConnectivity、共有のSwiftパッケージを使う。iOS/watchOSターゲットはXcodeGenの設定で管理し、Mac上でXcodeプロジェクトを生成できるようにする。依存ライブラリは最小限とする。

- **共有コア**: 再生プリセット、セッション、朝の評価、睡眠区間、重複除去と区間集計。Apple固有UIに依存させない。
- **音声**: 端末内で生成する一般的なモノラルビートとノイズ。ビートの有無を切り替えられる。周波数は実験用パラメータであり、医学的に最適と表示しない。ピーク制限と滑らかな開始・終了。再生中の時間管理は音声処理側の時間に基づき、バックグラウンドUIタイマーだけに依存しない。
- **睡眠取得**: iPhoneのHealthKitでsleepAnalysisを読み取り、Apple Watch由来のソースを優先する。ソース・サンプルID・取得時刻を保持。他のアプリや手入力を黙って同じ記録に混ぜない。
- **区間集計**: 就床を睡眠に加算しない。Core/Deep/REM/睡眠段階不明の区間の和集合を睡眠時間とする。同一ソースの重複を除き、日付境界をまたぐ夜と昼寝を区別する。異なるソースに矛盾があれば選択したソースを明示する。
- **Watch連携**: 最新の表示用要約はapplication context、評価イベントはキューで同期。各イベントにUUID、作成時刻、更新時刻を持たせて重複排除する。転送完了前は同期待ちを表示する。OSの健康データ同期を独自に再実装しない。
- **保存**: セッションと評価を端末内に保存。Watchに同期するのは必要な要約だけ。クラウド・解析SDKは使わない。削除機能を用意し、取り込んだ表示用データと自分の記録を消せる。Apple Health側の原本は変更しない。

## 権限と状態

HealthKitは初めて睡眠記録を見る時に読み取りのみ要求する。Watchの夜間センサー権限やワークアウトは使わない。権限要求が完了しても読み取り許可を判定したと表示しない。HealthKitなしでも音声再生と朝の自己評価は使える。

再生状態はidle/playing/stopped/interrupted/failedを区別。再起動時に前回の未終了セッションを再生中とみなさず、終了時刻不明として扱う。タイマー終了後に再生中表示を残さない。保存失敗・音声初期化失敗・通信失敗は表示する。

Watch未所持・未接続でもiPhone単独で動く。Watchの評価とiPhoneの評価が競合した場合は更新時刻を比較し、同一夜の最新の評価を採用する。過去イベントの再配送で新しい値を上書きしない。

## 成功条件と検証

- ロックしたiPhoneで設定した時間だけ音が鳴り、フェードアウトして終了する。
- 音声の上限・周波数・非有限値・フェードとタイマーの境界を共有ロジックのテストで検証する。
- 欠測、重複、就床＋睡眠の重なり、日付またぎで時間を誤集計しない。
- Watchのオフライン評価が再接続後に一度だけ取り込まれる。
- 読み取り拒否／睡眠未同期を安全に扱い、独自に睡眠段階や改善率を捏造しない。
- MacでiOS/watchOS両ターゲットをビルド。実機でHealthKit、Watch通信、ロック・通話・音声出力先変更、一晩の電池消費を確認する。Linuxで通せる静的検証と実機検証は区別して報告する。

## 開発とリポジトリ

ローカルの空のGitリポジトリを利用する。GitHubはユーザー指定に従い公開リポジトリ dieu-detruit/somni を作成する。公開配信・App Store提出はこの実装の完了条件にはしない。

現在の環境はLinux、SwiftとXcodeは未導入。ここではソースと設定、テストと手順を作成できるが、Apple向けのビルド成功や実機動作の完了を主張できない。Macと署名用Apple Developer Teamの設定は実機導入時に必要。

## 将来の判断

記録がたまり、ビートの有無や音の好みを比較できてからフィードバックの有用性を判断する。Watchでのリアルタイム制御を追加する場合は、まず実データの取得遅延・実行時間・電池・睡眠判定精度の検証を独立して行う。翌朝の振り返りという現行仕様に検証なしで組み込まない。
