# Audio exploration, day journal and analysis export

Implementation scope delegated by the user. No automatic external transfer of personal data.

- Preserve previous presets: existing volume remains master gain; add independently adjustable ambience gain and beat gain with defaults 1, plus beat rate default 4 Hz. Old saved settings decode to the same sound. Select 1/2/3/4/6 Hz as explicitly exploratory values, not efficacy claims. Keep 180-Hz base carrier; other tone is carrier plus beat rate. Beat mode retains its explicit enable/disable behavior. Allow ambience zero with audible beats. Smooth layer gains and rate changes without phase discontinuities; respect peak and timer limits.
- Add an iPhone journal for sleepiness (point event with optional severity 1–5), bedtime (point event), nap and morning return-to-sleep (intervals). Default to now; allow backdating, notes, edit and delete. Require valid intervals; distinguish self-reported events from HealthKit estimates and playback start. Record event time, creation/update time and timezone. Intervals may cross midnight. Do not force daytime events into the previous night's date.
- Provide explicit export via system share sheet, retaining full time series, not screenshots. Versioned ISO-8601 JSON bundle is authoritative; CSV tables make review easy. Include playback sessions and setting changes, morning ratings, journal events, all available sleep intervals, source IDs/selection and fetch times, app/schema/audio version and timezone metadata. Do not fabricate unseen raw Apple graphs. HealthKit export should include a user-selected calendar-date range of full-day sleep samples, covering naps/morning sleep; share available data with explicit coverage and query failures. Permission denial cannot be distinguished from no samples.
- Export has a clear preview/description stating included health data and notes; user explicitly invokes share. No network upload or SDK. Temporary export files are cleaned and protected; export deletion does not delete Apple Health records. Local data persistence must remain transactional and old records compatible.
- Initial UI remains Japanese; repository documentation English. Personal experiences are not public documentation. No realtime feedback feature in this release.
- New core behavior tests: old settings decode, finite/clamped new settings, independent layer isolation, beat rates/timing/fades, old persisted state migration, invalid intervals, JSON ISO timestamps, CSV quoting, duplicate health sample handling and full-day range boundaries.
